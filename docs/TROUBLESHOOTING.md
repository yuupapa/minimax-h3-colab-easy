# 困ったとき

| 状況 | 次にすること |
|---|---|
| ログイン・認証が必要 | 本人がColabにログイン。パスワードやコードをLLMへ送らない |
| A10080GBを選べない | GPU割当は保証されない。別GPUで続けず、購入せず終了する |
| RAMやディスク不足 | ハイメモリと実割当を確認。無理にモデルを取得しない |
| local-scratchが無い | 自動で `/content/h3-easy-cache` を選択。環境と共有する空き205GiB未満なら取得前に停止 |
| ドライバ580未満 | この固定CUDA13構成では停止。Macへドライバを入れず、対応する標準Colabランタイムを確認 |
| 残CU・使用率の入力エラー | Colabのリソース画面を開き、実際の値を入力。AI Proラベルだけで残量を推測しない |
| ライセンス確認で止まる | 本人がライセンス・地域・用途・クラウド場所を確認。AIが勝手に同意しない |
| セットアップの失敗 | 表示された段階とログ末尾を確認。同じVMで再実行するとキャッシュは再利用。バージョンを勝手に最新へ変更しない |
| 時間枠に達した | 処理は停止。生成済みMP4があれば速やかに保存。上限時間にはGPU終了要求が出て一時ファイルが消える場合がある |
| 生成済み・中断記録のエラー | 保存済み/部分生成ファイルを確認。本人が再試験を許可したらNEW_RUNをオンにして入力セルを実行。許可は1回だけ消費し、失敗後も自動再試行しない |
| ZIPが落ちてこない | ファイル一覧から `/content/h3-easy/outputs/` のMP4、または `/content/h3-easy/` のZIPを保存 |
| 自動GPU終了が不明 | ランタイムメニューで接続解除して削除。リソース画面の使用率0・稼働0件を確認 |
| LLMがブラウザを操作できない | READMEのColabアップロード手順を利用者へ渡し、次に押すセルを具体的に案内する |
| ファイル取り込みの承認・拡張設定で止まる | 実際の承認への本人応答を待つ。本人が手動で取り込む方法を案内し、別経路で承認を回避しない。公開後はColabボタンでローカルファイル取り込みを省ける |

エラーでもGPU接続は消費が続く場合があります。作業を終えるときはGPUの終了確認まで行ってください。


## ファイル選択の待機・タイムアウト

Colabの画像入力は出力iframe内にあります。操作ツールのfilechooserイベントがタイムアウトしても、通常のMac「開く」画面が既に表示されている場合があります。新しい選択画面を重ねて開く前に、現在の画面を確認してください。

- `.ipynb`だけが有効でPNGが選択不可なら、画像用ではなくノートブック読み込み用の画面です。キャンセルして画像入力の「ファイルを選択」を1回だけ開きます。
- Macの「開く」画面では⌘ShiftGで移動画面を開き、表示を確認して画像の絶対パスを入力。Returnで画像が選択されたことを確認して「開く」を押します。移動画面が開く前に貼り付け・Returnをまとめて送らないでください。
- ファイル選択APIを使うエージェントはクリック前にイベント待機を開始し、Promiseのタイムアウトを捕捉します。クリックとSpaceを無条件に続けて押すと別の選択画面が残る場合があるため、表示を確認してから次の操作を決めます。
- 権限拒否・ブラウザの安全警告と技術的タイムアウトは区別します。実際の拒否や未承認の権限を別経路で迂回しません。現在のブラウザセッションで入力セルを実行し直す必要がある場合があります。別タブの古いwidgetは使いません。

2026-10-11のCPU診断で、配布版と同じ単一ファイルAPIから猫PNG1枚の送信・保存・Pillow正規化が成功しました。GPU生成の検証ではありません。GPUを割り当てたまま長いファイル選択を待たず、選択手順の問題を解決してから承認されたGPU試験へ進みます。
