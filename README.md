# MiniMax H3・Colabセットアップキット

[▶ T2V / I2V・720pをColabで開く](https://colab.research.google.com/github/yuupapa/minimax-h3-colab-easy/blob/main/MiniMax_H3_T2V_I2V_720p_DEV_Colab.ipynb)

**同じ環境で、1本ずつ入力を変えて続けられます。指定した本数の有限キューも順番に生成します。** 各モード1本までの試作制限は撤去しました。モデル・依存はColab内へ準備し、Macへ大容量モデルを入れません。

1. 既存Googleアカウントでログインし、利用条件、今回の本数・CU上限・画像送信を確認します。
2. 文章・本数を準備し、A100・ハイメモリへ接続。実際の残CU、CU/時、接続経過分を入力します。
3. 入力 → セットアップ → 生成 → ZIP保存。次の文章・画像・seedへ変えるときは入力 → 生成。環境と取得済み重みを再利用します。I2Vは画像の表示確認後に入力セルだけ再実行します。
4. 作業終了・CU期限に近づいたときは完成分を保存し、**ランタイム → ランタイムを接続解除して削除**。使用率0・稼働0を確認します。

GitHub URLをClaude・Codex等へ渡す場合は[AGENTS.md](AGENTS.md)も読ませてください。本人ログインやモデル条件の判断は必要です。

## 本数・入力・再開

| 入力 | 動作 |
|---|---|
| `VIDEO_COUNT` | 1〜100の指定本数だけ生成。既定1。無制限のループはありません |
| `PROMPT` | 通常の文章。`PROMPTS_JSON`が空なら本数分に使用 |
| `PROMPTS_JSON` | 別々の文章を使う場合のJSON配列。件数は本数と一致させます |
| `SEED` | 開始seed。キュー内では1本ごとに+1 |
| 文章・画像・seed・本数・方式の変更 | 入力セルを再実行すると新しいキューを作成。以前の動画は保持 |
| 同じ入力で生成セルを再実行 | 完成済みの結果を返し、重複生成しません |
| `NEW_RUN` | 同じ入力で新しく追加したい場合だけオンにして入力セルを再実行 |
| `RESUME_FAILED_QUEUE` | 現在停止・失敗した同じキューを明示的に再開。完成分を飛ばし未完成分だけ実行 |

例: `VIDEO_COUNT=3`、`PROMPTS_JSON=["A red boat moves.","A blue boat moves.","A green boat moves."]`。入力セルで実際の文章・本数・seedを確認してから生成します。NEW_RUN/RESUME_FAILED_QUEUEは入力時に消費され、生成セルの再クリックでは再試行を許可しません。

T2V/I2Vは同じFL2VA環境です。方式変更時は旧画像を外してモード確認で一度停止。I2Vへ戻る際はその方式で始点画像を選び、内容・向きを確認します。1キューは1方式・画像1枚までで、その画像を指定本数に使います。次のキューでは別の画像を使えます。

停止には **ランタイム → 実行を中断** を使います。エラー・中断で残りの生成を止め、完成済み個別ZIPを保持。保存セルは現在のキューの完成分だけをまとめ、複数本は `clip_001/` 等へ格納します。失敗した未検品動画は完成分に含めません。再開時も過去ZIPや出力フォルダを消しません。旧キューは `/content/h3-fl720-dev/outputs` と同領域のZIPに残ります。R2Vは `/content/h3-r2v-dev` です。VM削除でクラウドの一時ファイルは消えるため、作業終了前に端末へ保存してください。

同じVMではセットアップ・重み取得を共有します。各動画は既存の単発生成コードを順に呼び、モデルプロセスは動画ごとに読込み・終了します。モデルがGPUに常駐したままの連続生成とは異なります。

## 環境・CU・保存

A10080GB、RAM約167GiB（空き140以上）、driver580以上。空きキャッシュ180GiB＋環境25GiB、同じディスクなら205GiB以上を要求します。Google AI Proの200CCU特典と実際の残量は別で、GPUの割当も保証されません。[Google公式案内](https://support.google.com/googleone/answer/14534406?hl=en)

720pのCU上限は既定5CUですが、試作時の固定5CU上限は撤去しています。本人が指定した正の有限値・残量以内を使います。入力変更・キュー再開・方式変更で開始時刻や締切は延長しません。上限変更は同じセッション内では拒否し、新しいランタイムで決め直します。

入力使用率から時間に換算し、85%で処理を停止、100%で終了要求。実時間の請求保証ではありません。残量・使用率を監視し、期限までに完成分を保存・GPU削除してください。タイマー満了による自動終了はGPU未検証です。追加購入、新規有料契約、自動課金、Drive全体マウント、トンネル、認証トークン要求は行いません。切断中にファイルパネルを開くと自動でGPUが割り当てられる場合があるため、GPU禁止中は開かないでください。

新しい画像は権利・写った人物の同意・Colab送信を確認し、正規化表示で必ず一度停止。元画像のEXIF等も送信され得ます。画像は出力ZIPへ同梱しません。生成物をGitHubへ自動公開しません。

## 検証範囲とライセンス

T2V/I2Vは別クリーンVMで各1本の生成・端末保存・全動画/音声デコード・GPU削除を確認済み。R2Vも参照1枚・1本の実測があります。今回の連続キュー、入力変更、有限複数本、停止・再開はGPUなしのモック検証です。新しい連続制御を実GPUで再検証したとは扱いません。

| 方式 | 過去の生成処理実測 | 出力 |
|---|---:|---|
| T2V720 | 215.306秒 | 1280×736→上下8px crop1280×720、124frames/24fps、5.175秒 |
| I2V720 | 182.119秒 | 同上 |
| R2V720 | 180.00秒 | 同上 |

生成処理はconditioning/denoise/decodeで、環境導入・取得・待機は含みません。背景や細部のにじみ、尾の上端切れ等があり、完全一致・品質・速度を保証しません。音の聴感は未評価。現行720pは指定5秒のみ。6秒、別GPU、API専用フル2K、ネイティブ1080pは含みません。[FL720記録](docs/FL720_CANDIDATE.md)／[R2V記録](docs/R2V_VALIDATION.md)

H3、Diffusers、ModelTC、LoRAの固定版・固定67依存を継続。[固定仕様](docs/FL720_SOURCE_AUDIT.json)。モデル生成本体と依存は今回変更していません。初期同意は全てオフです。
